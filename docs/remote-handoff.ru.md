# Явная передача просмотра

[English](remote-handoff.md) · [Улучшения](roadmap-delivery.ru.md)

Обновите плеер и CLI управления, затем выполните `ott handoff SOURCE TARGET`.
Источник продолжит играть. Получателю нужен тот же настроенный источник/аккаунт
и однозначный стабильный отпечаток канала `channel-v1`. Для обычного M3U он
вычисляется локально из точного URL потока; независимо подписанные или
переписанные URL безопасно не совпадут. Исходный ID провайдера не передаётся. Подбор по похожему имени, передача паролей
или URL потока не выполняются. Версия 1 поддерживает эфир/архив M3U, Xtream и
Stalker; фильмы, сериалы и непрерывная синхронизация истории не поддерживаются.

`playback_handoff_export` принимает пустые параметры и возвращает `data.handoff`
с `version: 1`, `provider`, `source_id`, `item_id`, `kind`. Для архива добавляется
целое `archive_start`: текущая точка просмотра в Unix-секундах.
`playback_handoff_import` принимает только `{"handoff": ...}`. Получатель
проверяет источник, каталог, доступность архива, родительские ограничения,
режим киоска и актуальность сеанса, затем получает поток своим провайдером.

Успех содержит `data.dispatched: true` и `kind`. Это подтверждение передачи
запроса воспроизведения, а не наличия декодированного изображения или звука HDMI.
Ошибки ограничены машинными кодами; лишние поля отвергаются. Формат и полный
список кодов: [описание протокола](remote-handoff.md).

Используйте отдельные права оператора на экспорт/импорт и защищённое подключение
к серверу. ID источника служит сопоставлению, но не даёт доступа к аккаунту.
Проверка: `node tests/test_remote_handoff.cjs`.
[Инструкция сервера](https://github.com/open-ott-play/ottplay-control-server/blob/main/docs/reliable-control.ru.md).
