# Улучшения надёжности и медиатеки

[English](roadmap-delivery.md) · [Wiki](wiki/Home.md) · [Архитектура](architecture.md)

Здесь описан код ревизии, из которой опубликована страница. Старый релиз не получает эти функции
автоматически. Плеер, сервер управления с CLI и отдельное Android-приложение —
разные сборки; обновление одной не обновляет остальные.

![Компоненты и границы доверия](diagrams/roadmap-components.svg)

[Измеренный объём и график сравнения](roadmap-size.ru.md) приведены отдельно;
скорость выполнения и воспроизведение на устройствах — другие проверки.

## Реализованные пункты

1. **Проверка изображения и звука.** [Информация → Звук](audio-video-check.ru.md)
   загружает с here.now восьмисекундный ролик (нужен интернет) с раздельными
   тонами и вспышками. Загрузка начинается только по команде **Воспроизвести**,
   не при старте приложения; в пакетах плеера медиафайла нет.
   Используется основной HTML5-декодер, только при простое или прямом эфире.
   История просмотра не меняется. [Описание ролика](../diagnostics/README.md).
2. **Возобновляемая настройка Local/Home.** CLI умеет планировать, применять,
   продолжать и проверять профиль. Перед повтором записи проверяет сохранённые
   значения. [Инструкция сервера управления](https://github.com/open-ott-play/ottplay-control-server/blob/9b28c08eefca3948c78336e7e16a45e6fc492e31/docs/reliable-control.ru.md).
3. **Ограниченное восстановление воспроизведения.** Временные ошибки HLS/Shaka
   используют конечный бюджет повторов. Ошибки авторизации и неподдерживаемый
   DRM завершают попытку. Смена канала/источника и Stop отменяют старые операции.
4. **Сохраняемые ограничения качества.** Максимальные высота и битрейт ограничивают
   адаптивный выбор. Переход на другой декодер не должен обходить ограничение.
5. **Предпочтения дорожек в native Android.** Отдельное приложение запоминает
   язык, назначение и подпись дорожки, Auto и выключенные субтитры; индекс дорожки
   другого потока не используется как предпочтение.
6. **Ограниченные ключи управления.** Сервер выдаёт интеграции права только на
   заданные устройства и действия, без административного ключа.
7. **Явное сопоставление XMLTV.** Канал плейлиста привязывается к конкретному
   источнику EPG и XMLTV ID. [EPG и доступность](guide-binding-accessibility.ru.md).
8. **Фильмы и сериалы Xtream.** Загружается выбранный каталог, эпизоды — после
   открытия сериала. [Контракт медиатеки](xtream-media.ru.md).
9. **Доступность классического интерфейса.** Списки сообщают выбранный элемент,
   диалоги удерживают и возвращают клавиатурный фокус, уведомления имеют live region.
10. **Сохраняемые исходы команд.** Ограниченный журнал сервера хранит сведения о
    дубликатах и результате. После перезапуска команды вслепую не повторяются.
11. **Передача просмотра устройству.** Передаются ссылки на эфир/архив того же
    настроенного источника; получатель сам получает URL. [Контракт](remote-handoff.ru.md).
12. **Явные резервные потоки.** Для прямого эфира можно задать альтернативы,
    использующие тот же конечный бюджет. [Качество и повторы](playback-stream-policy.ru.md).
13. **Восстановление пакетных настроек.** Для поддерживаемых записей в native
    localStorage работает журнал отката. [Гарантии хранения](settings-recovery.ru.md).

## Языки и совместимость

В плеере 88 языковых каталогов. Семь новых подписей качества и медиатеки
переведены во всех; остальные новые меню используют уже переведённые строки.
Проверяются ключи, параметры подстановки и согласованные исключения.
Полные инженерные инструкции новых функций доступны на английском и русском.
[Локализованные входные страницы](readme/README.md) — краткие инструкции запуска;
они не означают перевод всей исторической документации на 88 языков.

Классическая сборка сохраняет синтаксис ES5. Возможности кодеков, Web API,
хранилищ и native-интеграций зависят от устройства. A/V-проверка ограничена
основным управляемым HTML5-путём; подменяющие его движки устройств, в том числе
PC2/Video.js и нативные, исключены. Явная привязка EPG работает через hosted/native XMLTV.
Старые внешние companion-протоколы могут её не поддерживать. Проверка на самом
устройстве остаётся отдельным этапом.

## Повторение проверок

```sh
npm ci
npm run typecheck
npm run test:localization
npm test
npm run build:server
npm run check:es5
npm run check:size
python3 scripts/check-av-diagnostic.py diagnostics/av-v1.mp4
```

Последняя команда требует FFmpeg/FFprobe: декодируются оба аудиоканала,
проверяются энергия, разделение и тишина. Наличие AAC-дорожки само по себе
не доказывает наличие звука. JS-тесты проверяют отмену, ошибки записи,
восстановление после перезапуска, смену источника и некорректные входные данные.
Проверка объёма учитывает и дополнительные модули провайдеров.

Для сервера управления: `go test -race ./...`, `go vet ./...`,
`python3 -m unittest discover -s tests`. Для native Android — тесты предпочтений
дорожек и резервных копий, затем debug APK. Результат CI относится к конкретному
коммиту, а не к любым последующим изменениям.

## Проверка на устройствах перед выпуском

- На телевизоре проверить левый/правый звук, вспышки, Stop и возврат к эфиру.
  Тесты декодера не доказывают звук HDMI или плавность изображения.
- Проверить недоступный поток, отказ резервного URL, смену канала во время
  повтора и фактическое ограничение качества выбранного декодера.
- Проверить списки и диалоги клавиатурой, пультом и доступным экранным диктором.
- Привязать похожие названия каналов к разным XMLTV ID и проверить программу.
- Прервать применение тестового профиля, перезапустить сервер, продолжить и
  проверить. Передать просмотр в совпадающий и несовпадающий источник.
- В native Android сменить потоки с другим порядком дорожек, перезапустить
  приложение и проверить Auto, выключенные субтитры и выбранный язык.

Отправленная команда, сохранённые настройки, декодированный ролик и пройденные
unit-тесты — разные подтверждения. Их нельзя подменять друг другом при
[выпуске релиза](../RELEASING.md).
