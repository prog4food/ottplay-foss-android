# Автозапуск OTTPlay как домашнего экрана Android

[English instructions](android-distributions.md#optional-startup-as-the-android-home-app)
· [Сборка Android](../android/README.md)

В Capacitor APK предусмотрен дополнительный компонент
`play.ott.foss/.HomeActivity`, который открывает существующий `MainActivity`.
По умолчанию он выключен. После его включения и назначения домашним экраном
Android сможет открывать OTTPlay при запуске Home. **Кнопка «Домой» тоже будет
возвращать в OTTPlay.** Это не режим «один раз открыть плеер при загрузке,
оставив штатный лаунчер домашним экраном». Если прошивка имеет собственный
проверенный выбор приложения для автозапуска, для такого сценария удобнее он.

Для этого режима не нужны boot receiver, постоянная фоновая служба, разрешение
на показ поверх других приложений, служба специальных возможностей или
назначение приложения администратором устройства. Начиная с Android 10 запуск
Activity из фона ограничен: возможность получить `BOOT_COMPLETED` сама по себе
не разрешает открыть интерфейс. Официальная документация:
[домашнее приложение](https://developer.android.com/work/dpc/dedicated-devices/cookbook#be-the-home-app),
[ограничения фонового запуска](https://developer.android.com/about/versions/10/privacy/changes#background-activity-starts),
[исключения для broadcast](https://developer.android.com/develop/background-work/background-tasks/broadcasts/broadcast-exceptions).

Ниже — порядок настройки и проверки для Android 11. Наличие компонента в коде
или успешная сборка **не подтверждают автозапуск на конкретном проекторе**.
Результаты настоящей перезагрузки и включения после выключения нужно фиксировать
отдельно: производитель может менять поведение Home.

## Подготовка и сохранение штатного лаунчера

Нужен APK с обоими компонентами — `HomeActivity` и `HomeSetupActivity`,
подписанный тем же сертификатом, что установленный `play.ott.foss`. В старых APK
одного или обоих компонентов может не быть. Используйте обычное обновление
поверх приложения: оно сохраняет данные, профили и регистрацию удалённого
управления. Не удаляйте приложение, не очищайте его данные и не обходите ошибку
подписи принудительным понижением версии.

Из `adb devices -l` выберите точное устройство. Вместо заглушки укажите его
ADB serial; это не готовый сетевой адрес. В примерах используется основной
пользователь `0`. Если `am get-current-user` показывает другое значение,
замените номер пользователя во всех последующих командах.
Если для устройства используется отдельный ADB-сервер, добавляйте его прежний
параметр `-P PORT` ко всем командам `adb`, включая поиск устройств. Продолжайте
использовать тот же сервер и авторизованные ключи.

```sh
adb devices -l
OTT_ADB_SERIAL='REPLACE_WITH_ADB_DEVICE_SERIAL'
adb -s "$OTT_ADB_SERIAL" install -r /path/to/ottplay-foss-android-full.apk
adb -s "$OTT_ADB_SERIAL" shell am get-current-user
adb -s "$OTT_ADB_SERIAL" shell cmd package resolve-activity --brief --user 0 \
  -a android.intent.action.MAIN -c android.intent.category.HOME
```

Запишите выведенный компонент штатного Home в формате `package/activity`
вне самого плеера и сохраните его в переменной ниже. Не угадывайте имя пакета.
Если вывод указывает на системный выбор приложений или приложение не найдено,
сначала назначьте заведомо рабочий штатный Home. Сам лаунчер оставьте
установленным и включённым.
На некоторых проекторах системный выбор также показывает `FallbackHome` под
именем «Settings». Это временный экран загрузки Android, а не рабочий лаунчер.
Для отката выбирайте именно лаунчер производителя. Экран настройки не считает
`com.android.settings/.FallbackHome` безопасной заменой.

```sh
OTT_PREVIOUS_HOME='REPLACE_WITH_RECORDED_HOME_COMPONENT'
```

## Включение режима Home

Откройте встроенный экран настройки:

```sh
adb -s "$OTT_ADB_SERIAL" shell am start --user 0 \
  -n play.ott.foss/.HomeSetupActivity
```

Выберите **Включить**, подтвердите изменение, затем выберите OTTPlay в системном
выборе домашнего приложения. Само открытие экрана ничего не меняет. После
подтверждения OTTPlay включает собственный компонент: серийная прошивка может
запрещать `adb shell pm enable` для компонентов чужого приложения. Root и
отладочная сборка для этого не нужны.

Проверьте результат и один раз откройте Home вручную:

```sh
adb -s "$OTT_ADB_SERIAL" shell cmd package resolve-activity --brief --user 0 \
  -a android.intent.action.MAIN -c android.intent.category.HOME
adb -s "$OTT_ADB_SERIAL" shell am start --user 0 \
  -a android.intent.action.MAIN -c android.intent.category.HOME
```

В качестве Home должен определяться alias OTTPlay, а последняя команда должна
открыть плеер. При необходимости используйте системный выбор домашнего
приложения. Если прошивка не предоставляет работающий экран выбора,
авторизованный оператор ADB может назначить Home после включения компонента
в самом приложении:

```sh
adb -s "$OTT_ADB_SERIAL" shell cmd package set-home-activity --user 0 \
  play.ott.foss/.HomeActivity
```

Снова проверьте результат. Если ни один штатный способ не работает,
остановитесь: отключать лаунчер производителя
для принудительного выбора не требуется. Android описывает этот механизм как
[роль Home](https://developer.android.com/reference/androidx/core/role/RoleManagerCompat#ROLE_HOME).

После смены Home **подождите не менее 30 секунд перед `adb reboot`** и снова
проверьте фактически выбранный компонент. Сообщение `Success` и наличие роли
Home ещё не подтверждают сохранение выбора на диск. В AOSP Android 11
[запись предпочтений PackageManager отложена на 10 секунд](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-11.0.0_r48/services/core/java/com/android/server/pm/PackageManagerService.java);
немедленная перезагрузка через ADB может обойти штатное завершение Android.
Это относится и к восстановлению прежнего Home.
Такая пауза даёт время на сохранение, но не гарантирует поведение любой прошивки.
Если роль уже принадлежит OTT, но команда определения Home показывает другое
приложение, повторное подтверждение **Включить** открывает системный выбор Home.
Ориентируйтесь на фактический компонент и результат перезагрузки.

Ручная команда `am start` выше — только предварительная проверка. Она **не
доказывает автозапуск**. Проверьте физические кнопки «Домой» и «Назад», возврат
из другого приложения и запуск обычным значком. Должен работать один сеанс
плеера с прежними профилем, именем удалённого управления и движком воспроизведения.

Системные настройки и прежний лаунчер можно открыть явно:

```sh
adb -s "$OTT_ADB_SERIAL" shell am start --user 0 -a android.settings.SETTINGS
adb -s "$OTT_ADB_SERIAL" shell am start --user 0 -n "$OTT_PREVIOUS_HOME"
```

Вторая команда открывает прежний лаунчер, но не делает его домашним экраном
по умолчанию.
Некоторые прошивки не обрабатывают `android.settings.SETTINGS`. В этом случае
используйте проверенный компонент настроек именно этого устройства; имя пакета
производителя нельзя угадывать.

## Проверка на устройстве

1. Зафиксируйте версию APK, текущий Home, boot ID и uptime. После описанного выше
   ожидания выполните обычную перезагрузку либо
   `adb -s "$OTT_ADB_SERIAL" reboot`, когда воспроизведение можно прервать.
2. После подключения устройства проверьте завершение загрузки, uptime и
   foreground Activity. Boot ID должен отличаться от записанного перед
   перезагрузкой. **Во время наблюдения не отправляйте `am start`, нажатие
   Home или команду удалённого запуска:** иначе тест перестанет проверять
   автоматическое открытие.
3. Убедитесь, что OTT появился самостоятельно и удалённая регистрация вернулась
   после восстановления сети. Запуск интерфейса и воспроизведение канала — разные
   проверки. Заставка не подтверждает готовность: проверьте изображение, звук
   и продвижение воспроизведения согласно выбранному режиму плеера.
4. Отдельно проверьте нормальное выключение и последующее включение, отличая их
   от standby/resume. Успешная программная перезагрузка не подтверждает холодный
   старт проектора.
5. Проверьте включение с задержкой подключения Wi-Fi и восстановление после
   появления сети. Системные настройки должны оставаться доступными.
6. После следующего подписанного обновления APK снова проверьте включённость
   alias, выбранный Home, профиль, удалённое управление и автозапуск. Сообщение
   установщика об успехе этого не доказывает. Force-stop не заменяет перезагрузку.

Команды для наблюдения после подключения:

```sh
adb -s "$OTT_ADB_SERIAL" shell getprop sys.boot_completed
adb -s "$OTT_ADB_SERIAL" shell cat /proc/sys/kernel/random/boot_id
adb -s "$OTT_ADB_SERIAL" shell cat /proc/uptime
adb -s "$OTT_ADB_SERIAL" shell dumpsys activity activities
adb -s "$OTT_ADB_SERIAL" shell cmd package resolve-activity --brief --user 0 \
  -a android.intent.action.MAIN -c android.intent.category.HOME
```

## Возврат штатного Home

Сначала восстановите записанный компонент и проверьте, что система выбирает его:

```sh
adb -s "$OTT_ADB_SERIAL" shell cmd package set-home-activity --user 0 \
  "$OTT_PREVIOUS_HOME"
adb -s "$OTT_ADB_SERIAL" shell cmd package resolve-activity --brief --user 0 \
  -a android.intent.action.MAIN -c android.intent.category.HOME
```

Вместо команды можно выбрать записанный лаунчер в системных настройках Home.
Только после восстановления прежнего Home снова откройте встроенную настройку
OTTPlay и выберите **Отключить**. Экран не позволит отключить компонент, пока
OTTPlay остаётся домашним приложением или наличие замены нельзя подтвердить.

```sh
adb -s "$OTT_ADB_SERIAL" shell am start --user 0 \
  -n play.ott.foss/.HomeSetupActivity
```

После подтверждения отключения проверьте открытие записанного лаунчера:

```sh
adb -s "$OTT_ADB_SERIAL" shell am start --user 0 \
  -a android.intent.action.MAIN -c android.intent.category.HOME
```

Обычный значок OTTPlay остаётся доступным. Удалять данные плеера не нужно.

## Заставка проектора

Заставка Android может перекрывать уже работающий плеер. На X1BQ с Android 11
и LuminaOS 1.0.73 кнопка «Назад» закрыла заставку производителя. Для установки,
используемой как выделенный плеер, `screensaver_enabled` у пользователя `0`
изменён с `1` на `0`:

```sh
adb -s "$OTT_ADB_SERIAL" shell settings --user 0 get secure screensaver_enabled
# Необязательное изменение, после записи исходного значения:
adb -s "$OTT_ADB_SERIAL" shell settings --user 0 put secure screensaver_enabled 0
```

Для отмены верните записанное значение. Если оно отсутствовало (`null`),
используйте `settings --user 0 delete secure screensaver_enabled`. Эта настройка
не связана с выбором Home. Таймер отключения экрана на проверенном устройстве
оставлен прежним: окно OTT во время воспроизведения уже удерживало
`KEEP_SCREEN_ON`. Заставки других производителей могут не учитывать этот флаг.

## Аппаратная проверка: X1BQ, 19 октября 2026

Проверено на Android 11 с LuminaOS 1.0.73. На устройство поверх существующего
приложения установлен подписанный вариант стабильной версии 1.1.57 с изменениями
Home: `1.1.57-local.projector.dcd399cbed0d` (versionCode `10434`). Это локальная
проверочная сборка, а не отдельный опубликованный релиз.

После назначения Home и ожидания не менее 30 секунд две последовательные
программные перезагрузки открыли OTT самостоятельно: на предыдущей и на
окончательной сборке. В обоих случаях изменился boot ID, завершилась загрузка
Android, а `play.ott.foss/.HomeActivity` оказался активным примерно на 30-й и
33-й секунде uptime. Команды запуска и нажатия Home после reboot не отправлялись.
Обновление сохранило профиль Home и существующую регистрацию удалённого управления.

В более раннем опыте `adb reboot` примерно через две секунды после выбора Home
сохранил роль OTT, но вернул фактический Home на LuminaOS. Повтор с ожиданием
прошёл успешно; этот результат согласуется с отложенной записью Android, но
не доказывает, что каждая прошивка ведёт себя так же. Штатный лаунчер и его
настройки остаются установленными и доступными.

Затем пользователь отдельно выключил и включил проектор. Новая загрузка
снова получила другой boot ID и самостоятельно открыла `HomeActivity`;
роль Home и фактический компонент остались назначены OTT. Таким образом,
проверено и обычное включение кнопкой питания, а не только ADB reboot.
После этого включения пользователь подтвердил изображение канала и звук.
Запуск с намеренно задержанным подключением Wi-Fi отдельно не проверялся.
