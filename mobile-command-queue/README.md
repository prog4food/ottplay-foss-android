# mobile-command-queue

Capacitor plugin for the in-process command queue on iOS and Android. Loading the plugin or calling `start()` does not open a network socket. The player uses the native `post()` / `get()` bridge.

## Native bridge

```typescript
import { MobileCommandQueue } from "mobile-command-queue";

await MobileCommandQueue.start();
await MobileCommandQueue.post({
    data: { command: "popup_message", message: "Hello" },
    deviceId: "device-123",
});
const { commands } = await MobileCommandQueue.get({ deviceId: "device-123" });
commands.forEach((command) => handleCommand(command));
await MobileCommandQueue.stop();
```

`get()` drains pending commands for the requested device; an omitted or empty `deviceId` selects the broadcast queue. Commands expire after 60 seconds. Queues retain at most 50 commands per device (trim to 25) or 100 broadcast commands (trim to 50). Device IDs are limited to 128 characters and the number of device queues to 128. Each command is limited to 64 KiB of JSON; pending payloads, including accounting overhead, have a shared 1 MiB limit. `stop()` closes the listener, if enabled, and clears pending commands.

`src/index.ts` starts this internal queue and polls the broadcast queue and the player UUID queue through `get({ deviceId })` every 10 seconds. It does not set `local_poll_url`, which would also poll the HTTP endpoint. Non-Capacitor builds use a no-op web fallback. This plugin does not configure the browser/STB or Tauri command transports.

## Optional local HTTP control

In **Settings → Remote control → Local HTTP remote control**, enable the option (off by default). The player creates a cryptographically random device code and displays the listening port. Configure your proxy with this code as its Bearer token. Turning the option off closes the listener and clears the code; enabling it again generates a new code. The code and consent are excluded from settings backups.

The player uses the following native API after explicit opt-in:

```typescript
// token is the device code generated by the player settings.
const status = await MobileCommandQueue.start({ httpEnabled: true, token });
// status.port is the selected loopback port; status.httpEnabled is true.
```

The token must contain 32–256 URL-safe ASCII characters (`A–Z`, `a–z`, `0–9`, `_`, `-`). The listener binds only to `127.0.0.1`, preferring port 18081 and trying 18082–18090 if busy. A native `OTTPLAY_QUEUE_PORT` environment override pins a single port. Use the returned port; do not assume that 18081 was selected. Call `stop()` before changing the token.

Every HTTP request, including health checks, requires `Authorization: Bearer <token>`. The server grants no browser CORS access and has no unauthenticated OPTIONS endpoint. Do not expose or forward this listener to other hosts.

Supported authenticated routes:

- `POST /api/webhook/commands` (alias `/webhook/notify`) enqueues a JSON object.
- `GET /api/webhook/commands` (alias `/webhook/poll`) returns and drains a JSON array of commands.
- `GET /api/webhook/health` (alias `/webhook/health`) reports listener health.
- `?device_id=<id>` selects a device queue for command routes.

HTTP requests have a 5-second deadline, a 2 KiB request-line limit, an 8 KiB header limit, and a 64 KiB body limit. At most eight client connections are accepted concurrently. The queue limits above also apply to HTTP submissions.

Use the native queue regression harnesses, or `scripts/smoke-command-queue.sh` against an explicitly enabled listener with `QUEUE_HTTP_TOKEN` in the environment and its selected loopback `BASE_URL`. The smoke script never enables a listener; use a dedicated `DEVICE_ID` because the contract test enqueues and drains commands. See [mobile setup](../docs/capacitor-mobile.md).
