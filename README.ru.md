# OTT-play FOSS

[English](README.md) · [Краткий запуск на 88 языках](docs/readme/README.md) · [Вики документации](docs/wiki/Home.ru.md)

Открытый IPTV/OTT-плеер с общим интерфейсом для браузера, Smart TV, приставок,
настольных Tauri-приложений и мобильных Capacitor-приложений. Локальный
`ottplay-server` на Rust раздаёт интерфейс и предоставляет серверные функции.
Плеер использует ваш плейлист или аккаунт провайдера; подписка на каналы в него
не входит.

Это полное практическое руководство на русском языке. Подробные англоязычные
справочники по архитектуре и протоколам остаются основным источником инженерных
контрактов. Остальные языки имеют краткие инструкции из переводов интерфейса,
а не копии полного руководства. [Обзор реализованных возможностей, схемы и
границы поддержки](docs/roadmap-delivery.ru.md).

## Запуск без установки

Откройте [плеер в браузере](https://player.ottplay.here.now/) и выберите
**Попробовать демо**. Демо доступно и позднее через
**Настройки → Сменить провайдера → Demo**. Оно требует интернета и не требует
аккаунта провайдера. Демо-каналы MP4/HLS с движущейся таблицей **не содержат
звука**; отсутствие звука в них не диагностирует HDMI или динамики.

Отдельная проверка картинки и звука запускается через
**Информация → Звук → Воспроизвести**. Она загружает с here.now файл
`av-v1.mp4`; требуется подключение к интернету. В пакетах плеера ролика нет,
при запуске приложения он не загружается. Ролик воспроизводится
в основном управляемом HTML5-декодере. Проверку можно
запустить в простое или при просмотре эфира; архив, VOD и подменяющие основной
видеотракт движки устройств (включая PC2/Video.js и нативные) исключены.
После завершения восстанавливается прежний эфир, если
пользователь не остановил просмотр и не выбрал другой источник.
[Порядок проверки, ожидаемые тоны и схема хостинга](docs/audio-video-check.ru.md).

Для своего плейлиста:

1. Откройте **Настройки → Сменить провайдера → M3U / M3U8**.
2. Откройте **Выберите плейлист**, выберите свободную позицию и поле
   **Адрес плейлиста**. Введите полный URL вашего M3U/M3U8-плейлиста.
3. Сохраните поле и выберите **Загрузить плейлист**. При необходимости задайте
   название и параметры архива, предоставленные провайдером.
4. Выберите канал. Для другого провайдера используйте его собственный пункт
   настроек; ссылку VPortal вводите в поле VPortal, а не вместо M3U-плейлиста.

Язык меняется в **Настройки → Изменить язык интерфейса**. Поддерживаются 88
каталогов переводов и локализованные экранные клавиатуры. Набор доступных
возможностей зависит от провайдера и устройства.

В основном окне видео **Option + ←/→** на macOS или **Alt + ←/→** на
Windows/Linux перематывает на десять секунд назад/вперёд; на macOS также работает
**Command + ←/→**. Полноэкранный режим не обязателен. Сочетания общие для веба,
Tauri и Capacitor с аппаратной клавиатурой: локальные видео, VOD и архив каналов
при поддержке провайдером. В эфире без архива перемотки нет. Меню, поля ввода
и ограничения киоска сохраняют своё поведение.
[Подробности сочетаний](docs/browser-window-controls.md#playback-keyboard-shortcuts).

В PC-интерфейсе **R** включает другой случайный канал или видео из текущего
списка, не перемешивая его порядок. Клавиша работает в окне видео и списках
каналов/видео; поля ввода, диалоги, настройки и ограничения киоска сохраняют
приоритет. Привязки клавиш других устройств не меняются.

## Что умеет плеер

- **Эфир и медиатека.** HLS, DASH и обычные HTTP-потоки, M3U/M3U8,
  Xtream Codes, Stalker/Ministra, Plex и VPortal. Каталог Xtream загружает фильмы,
  сериалы и эпизоды по мере открытия; актуальный адрес определяется при выборе.
  Не каждый провайдер предоставляет архив или VOD. [Медиатека Xtream](docs/xtream-media.ru.md).
- **Ограничение качества.** В **Настройки → Настройки интерфейса** можно задать
  верхние пределы высоты видео и битрейта для управляемых HLS/Shaka-движков.
  Это выбор подходящего варианта потока, а не перекодирование. Нативные и старые
  TV-движки могут не поддерживать эти пределы.
- **Восстановление эфира.** Ограниченные повторы после временных ошибок и до
  трёх явно заданных резервных адресов через **Информация → Резервные потоки**.
  Архив и VOD не подменяются эфиром; ошибки авторизации не запускают перебор.
  [Подробности восстановления и качества](docs/playback-stream-policy.ru.md).
- **Программа передач.** XMLTV, поиск передач, напоминания, архив и продолжение
  просмотра. В поддерживаемом hosted/native XMLTV можно указать точный источник
  и ID канала через **Информация → Программа**. Привязка хранится для конкретного
  источника и канала; полного браузера всех XMLTV-кандидатов здесь пока нет.
  [Привязки и доступность интерфейса](docs/guide-binding-accessibility.ru.md).
- **Избранное и оформление.** Несколько списков, родительский PIN, темы
  Studio 2026, Classic и PLi-HD, настройка названий каналов, пиктограмм,
  прогресса и подсветки. Серверный, Tauri- и Capacitor-интерфейсы используют общие
  настройки отображения.
- **Настройки.** Экспорт и импорт JSON, локальное восстановление незавершённого
  импорта нескольких ключей, сравнение сохранённых значений для контроллера.
  Смена источника не должна применять оставшиеся ответы от старого источника.
  Журнал работает для поддерживаемого localStorage с одним писателем;
  пользовательские адаптеры сохраняют только best-effort откат.
  [Границы восстановления](docs/settings-recovery.ru.md).
- **Доступность.** Подписанные стандартные диалоги, удержание и возврат фокуса
  Tab, обозначение выбранной строки списка каналов и спокойные уведомления.
  Это конкретные улучшения, а не заявление о полной сертификации WCAG или
  проверке всех физических экранных дикторов.
- **Управление.** Пульт телевизора, клавиатура, сенсорный ввод, телефонная
  клавиатура, локальный HTTP-пульт и отдельный сервер команд. В контроллере
  доступны ограниченные по устройствам и действиям операторы, журнал результатов,
  возобновление применения профилей Local/Home и перенос эфира/архива на другой
  плеер с тем же настроенным источником. Нужны согласованные версии плеера,
  контроллера и CLI. [Общая схема](docs/roadmap-delivery.ru.md).
- **Диагностика.** HUD и журнал по явному включению, удалённая диагностика
  с разрешением устройства, проверка звука и изображения роликом с here.now.
  Счётчик кадров или принятая команда сами по себе не подтверждают изображение
  и звук на физическом телевизоре.

Отдельное [нативное Android-приложение](https://github.com/open-ott-play/ottplay-android)
сохраняет предпочтения аудио и субтитров по языку, роли и подписи дорожки,
а не по меняющимся индексам потоков. Это другой репозиторий и другая установка.

## Установка готовых сборок

Артефакты доступны в [GitHub Releases](https://github.com/open-ott-play/ottplay-foss/releases).
Выберите нужный канал выпуска и архитектуру. Наличие исходного кода в `main`
не означает, что он уже установлен на устройстве или опубликован на сайте.

- **macOS:** `.dmg` или `.app.zip`, отдельно Apple Silicon и Intel. Без настроенных
  сертификатов Apple сборка подписана ad-hoc, без Developer ID и нотариализации.
  Откройте приложение через контекстное меню Finder; подробности проверки
  подписи и установки — в [английском руководстве](README.md#macos).
- **Windows:** `.msi` или `.exe` для x64. Пакет может быть без цифровой подписи;
  сверяйте источник и контрольную сумму опубликованного артефакта.
- **Linux:** AppImage, DEB или RPM. Для AppImage может потребоваться разрешение
  запуска: `chmod +x ./OttPlay*.AppImage`. Подробности зависимостей и запуска
  приведены в [разделе Linux](README.md#linux).
- **iOS:** `.ipa` для самостоятельной установки. Файл из GitHub сам по себе
  не содержит вашего provisioning profile: нужны подпись через AltStore/Xcode
  либо действительное приглашение TestFlight. Публикация IPA не создаёт такое
  приглашение. [Подробная установка](README.md#ios-installation).
- **Android 7+:** `ottplay-foss-android-full.apk`, общий Capacitor-интерфейс.
- **Android 5.1–6:** `ottplay-foss-android-api22.apk`, тот же Full-интерфейс,
  требуется WebView 60 или новее. Для Android 4.4 этот пакет не предназначен.

Full и API 22 используют одну идентичность приложения и один сертификат
релизной подписи. Обновляйте совместимым пакетом, сохраняя данные. Отдельное
Kotlin/Compose-приложение не заменяет установленный Capacitor-плеер поверх него.
[Варианты Android и обновление через OTT](docs/android-distributions.md).

## Сборка браузерного плеера и сервера

Нужны Git, Node.js 22, npm и актуальный Rust stable. Команды выполняются из
корня репозитория; сервер раздаёт файлы относительно рабочего каталога.

```sh
git clone https://github.com/open-ott-play/ottplay-foss.git
cd ottplay-foss
npm ci
npm run build:server
cargo build --release -p ottplay-server
./target/release/ottplay-server --port 8080
```

Откройте [http://localhost:8080](http://localhost:8080). `build:server`
собирает браузерные/TV-артефакты с проверкой ES5. Полная `npm run build` также
готовит ресурсы для нативных оболочек. Для редактирования интерфейса есть
`npm run dev`; dev-сервер не заменяет backend-функции Rust-сервера.

Для нескольких XMLTV-источников задайте `EPG_URLS`, разделяя URL точкой с запятой:

```sh
EPG_URLS='https://example.org/guide.xml.gz;https://example.org/extra.xml' \
  ./target/release/ottplay-server --port 8080
```

Пример адресов нужно заменить своими. Разрешения браузера на CORS и смешанный
HTTP/HTTPS-контент сохраняются: страница по HTTPS не получает автоматический
доступ к произвольному HTTP-потоку. Используйте подходящий транспорт или
настроенный сервер. [Архитектура](docs/architecture.md),
[сборка и бюджет артефактов](docs/build-pipeline.md),
[локальные HTTP-инстансы macOS](docs/local-http-deployment.md).

### Tauri для рабочего стола

Нужны Rust и системные зависимости Tauri для выбранной ОС. После `npm ci`:

```sh
npx tauri build
```

Артефакты находятся в `target/release/bundle/`. Для разработки используйте
`npx tauri dev`. Перед локальной установкой на macOS ознакомьтесь с
[правилами доставки](docs/macos-local-delivery.md) и
[подписью и обновлением Tauri](docs/tauri-updater-notarize.md).
`build-local.sh` переустанавливает приложение и очищает WebKit-хранилище;
не запускайте его как безобидную проверку сборки без резервной копии настроек.

### iOS и Android Capacitor

Для iOS нужны macOS и Xcode; подпись для физического устройства настраивается
в Xcode. Для Android нужны Java 21, Android SDK 36 и Build Tools 36.0.0.

```sh
npm ci
npm run build:ios
npm run cap:ios
# Android: выберите нужную цель
npm run android:full
npm run android:api22
```

`android:full:release` и `android:api22:release` создают релизные APK; для
локальной подписи необходим keystore. Сборщик синхронизирует плагины и проверяет
упакованные ресурсы. Не копируйте устаревший `dist-mobile` вручную.
[Capacitor](docs/capacitor-mobile.md), [Android build](android/README.md),
[проверка устройств](docs/mode-b-device-smoke.md).

### Docker

```sh
docker run --rm -p 8080:8080 \
  -e EPG_URLS='https://example.org/guide.xml.gz' alvit/ottplay-foss:X.Y.Z
```

Замените `X.Y.Z` опубликованной стабильной версией. Серверный образ использует
musl/Alpine и поддерживает amd64/arm64. Образ публикуется продвижением
проверенного артефакта; push в `main` сам по себе не публикует контейнер.

## Управление и резервные копии

Для экспорта откройте **Настройки → Управление настройками → Экспорт настроек**.
Сохраните JSON в приватном месте: настройки источников могут содержать учётные
данные. Импорт выполняется в том же разделе. Локальное восстановление импорта
не является общей транзакцией между несколькими устройствами.

Сервер команд — отдельный компонент
[ottplay-control-server](https://github.com/open-ott-play/ottplay-control-server).
Подключение настраивается в **Настройки → Удалённое управление**. Выдавайте
интеграциям разрешения на нужные устройства и операции, а не общий токен
администратора. Для новой версии CLI доступны:

```sh
ott tv load Local plan
ott tv load Local apply
ott tv load Local resume
ott tv load Local verify
ott handoff living-room bedroom
```

Замените имена устройств своими. `plan` проверяет локальный профиль;
`apply` и `resume` требуют настроенного журнала контроллера. `verify` сравнивает
сохранённые настройки, но не доказывает доступность потока. Handoff требует
одного источника/аккаунта на обоих плеерах, поддерживает эфир/архив и не
останавливает исходное устройство. VOD, перенос паролей и произвольных
playback-URL в этот контракт не входят.
[Контракт handoff](docs/remote-handoff.ru.md),
[Протокол управления](docs/remote-workbench.md),
[надёжное управление и ограничения](https://github.com/open-ott-play/ottplay-control-server/blob/ee48d7246467ff259494ef2009c255fdc2c8de48/docs/reliable-control.ru.md).

## Проверка изменений и документации

```sh
npm run typecheck
npm run lint
npm run test:localization
npm run test:unified
npm run build:server
node scripts/check-es5.cjs --server-only
npm run check:docs
```

Полная матрица CI дополнительно проверяет нативные мосты, сервер, упаковку и
интеграцию с контроллером. Проверки реальных пультов, декодеров, HDMI и дикторов
выполняются на устройствах; модульные тесты их не заменяют. Для конкретного
изменения используйте проверки из соответствующего руководства.

Краткие README генерируются из действующих каталогов переводов:

```sh
npm run docs:generate
npm run check:docs
```

Не редактируйте сгенерированные инструкции вручную. Исправляйте строку
локализации либо общий генератор, затем обновляйте все языки. Генератор не
переводит инженерные руководства и не маскирует английский текст под готовый
перевод. [Правила и индекс языков](docs/readme/README.md).

[Отчёт «Процесс и результат»](docs/implementation-report.ru.md) содержит цветные
диаграммы, исправленные регрессии, измеренный объём и оставшиеся условия выпуска.
[Браузерная приёмка](docs/browser-compatibility.ru.md) объясняет матрицу,
проверку точного пакета и различие между локальными результатами и квалификацией RC.

Начните с [русской вики](docs/wiki/Home.ru.md) или [английской вики](docs/wiki/Home.md).
[Архитектура плеера](docs/architecture.md) описывает владельцев ресурсов,
провайдеры, жизненные циклы и границы общего ядра.
[Контракты воспроизведения](docs/playback-session-architecture.md) объясняют,
как не применять устаревшие асинхронные ответы после смены источника.

[Правила релизов](RELEASING.md) и [инструкция оператора](docs/release-workflow.md)
различают nightly, beta, RC и stable. Стабильная версия продвигает проверенные
RC-артефакты; наличие успешного локального теста не заменяет эту процедуру.
[Фаззинг RC](FUZZING.md) проверяет ограниченные кампании XMLTV и запросов портала.
